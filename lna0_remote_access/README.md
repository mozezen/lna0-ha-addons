# LNA0 Remote Access (HAOS application)

Separate from the existing LNA0 Agent. No incoming ports or host networking.
The HAOS app creates one outbound SniTun 0.47.0 connection, forwarding incoming
TLS traffic to an Nginx proxy bound on its *own* container loopback address.
TLS terminates at the HAOS app, not at Hetzner, and Nginx proxies to the
local Home Assistant Core HTTP service on port 80 (configurable).

## Status / release gate

**Integration candidate — not ready for unattended customers.** Boot defaults
to manual. The code and app package are installable, but a real working
public connection also requires all the following, not yet delivered:

1. Control Plane's Phase 2C features deployed with internal API restrictions.
2. Session Master deployed with authenticated credential delivery and automatic
   renewal into `/data/credentials.json`; no manual long-lived shared secret.
3. Nginx SNI frontend on Hetzner port 443 connected to the SniTun Gateway;
   DNS and ACME/DNS-01 certificate automation.
4. Valid public TLS fullchain/private key for the assigned customer hostname,
   accessible to the HAOS app under `/ssl` (provisioned independently per house).
5. HA reverse proxy trust configured narrowly for this app, correct real IP
   attribution, rate limiting, peer revocation, and external Companion-app tests.

Do NOT disable Nabu Casa during provisioning.

## Files

- `config.yaml`: HAOS app definition, no exposed host ports.
- `Dockerfile`: pinned Python 3.13 Home Assistant base plus SniTun 0.47.0.
- `remote_client.py`: TLS proxy orchestration, SniTun connection and reconnect.
- `/data/credentials.json`: generated by a future trusted provisioning agent.

### Credential file contract (the private file is NOT part of this package)

Only the authenticated Session Master may provide these values via a trusted
channel; do not paste them into chat, config.yaml, Git or app logs.

```
{
  "hostname": "<32 lowercase hexadecimal>.remote.55projects.com",
  "fernet_token": "<SniTun token from Session Master>",
  "aes_key": "<64 hex characters>",
  "aes_iv": "<32 hex characters>",
  "expires_at": "2026-11-09T12:00:00+00:00",
  "protocol_version": 2,
  "cipher": "aes-gcm-siv"
}
```

Protect this file with `0600` permissions, rotate credentials automatically.
The app refuses mismatched, expired or permissively stored credentials.

## Important security limitations

- TLS termination inside the app means **the HAOS host** must protect its
  certificate private key. Do not use a shared wildcard private key across
  different homes. Cert delivery and renewal remain to be implemented.
- SniTun does not authenticate Home Assistant users; HA login/MFA remains
  essential. Token expiry alone does not revoke an active tunnel.
- The standard EndpointConnector does not preserve the remote user's real IP
  when proxying to Nginx. Fail-safe client-IP attribution and HA trusted proxy
  settings must be addressed before public production use.
- App currently has NO automatic credential provisioning or rotation; it can
  reconnect only while its supplied credentials are valid. This is a deliberate
  release gate, not a complete finished product.
- Base container uses a pinned tag, not an immutable image digest; lock digest,
  obtain SBOM and scan image before production release.

## Unit tests

From this folder: `python3 -m unittest discover -s tests -v`

## Installation when dependencies are operational

Install as a local HAOS application in your controlled application repository.
The `public_hostname` option must match the assigned opaque route. Set
`gateway_host=remote.55projects.com` and `gateway_port=443` only after the
public ingress is connected to the SniTun Gateway. Mount the per-house TLS
certificate from `/ssl`. Do not start the app with a missing credential file.
